Zero-Loss Atomic Document Upload Protocol

In retail lending, borrower income documents (Bank Statements, ITRs, Property Title Deeds) often exceed 15–25 MB. Submitting entire applications with 8 attachments in a single HTTP request causes frequent mobile timeouts and corrupted multipart boundaries.

DhanSource implements a resilient 4-Stage Atomic Document Pipeline:

1

Stage 1: Application Draft Initialization

The client submits borrower profile data (Name, PAN, Mobile, Loan Amount). The server creates a MongoDB document in DRAFT status and reserves an official tracking number (e.g. DS2026-08119). No file binaries are transmitted in this request.

2

Stage 2: Client-Side Normalization & MIME Sanitization

On mobile (Android/iOS) or web, the file object is inspected. Binary headers are normalized to guarantee valid MIME types (application/pdf, image/jpeg, image/png). Dangerous characters in file names are stripped and suffixed with high-resolution timestamps.

3

Stage 3: Individual Atomic S3 Upload Streams

Each document (e.g. PAN_CARD, SALARY_SLIP_1, BANK_STATEMENT) is dispatched via an independent HTTP request using native fetch with automated exponential backoff (2 retries). If document 5 fails, documents 1 through 4 remain permanently verified in S3.

4

Stage 4: State Finalization & RM Dispatch

Once all mandatory documents are confirmed in S3, the client calls /submit. The application atomically transitions to SUBMITTED, records an audit log, and notifies the partner's designated RM via push notification and email.

Role-Based Access Control (RBAC) & Security

Comprehensive permission matrix, cryptographic standards, and authenticated session governance.

Cryptographic & Session Standards

🔑 Password Hashing (Argon2id)

Passwords are salted and hashed using Argon2id with memory cost 65536 KB, iteration count 3, and parallelism 4, providing unmatched resistance to GPU cracking.

🛡️ Stateless JWT Tokens

Cryptographically signed JSON Web Tokens (HMAC-SHA256) with strict 7-day expiration. Tokens carry sub (User ID), role, and email.

🔒 Multi-Tenant S3 Isolation

Documents uploaded to AWS S3 are segregated into secure paths: applications/{appId}/{docType}_{timestamp}.ext. Direct public listing is blocked.

Chapter 06

Hierarchy & Smart File Routing Engine

Mathematical routing rules connecting Partners to Universal RMs, and dynamically dispatching approved files to Specialized ASMs and RSMs.

1. The Universal RM Operating Principle

A central innovation of the DhanSource Capital platform is that an RM is NEVER constrained by loan type.

  • An RM is assigned geographically or by portfolio to specific Channel Partners.
  • Whether a partner submits a ₹50,000 Personal Loan or a ₹10 Crore Industrial LAP file, the file flows straight to their primary RM.
  • The RM acts as the field auditor, ensuring all pages are legible, statements are unencrypted, and signatures match before passing files upwards.

2. Smart Dynamic Routing Sequence (DOC_COMPLETE)

When an RM certifies an application as DOC_COMPLETE, the backend executes the following algorithmic dispatch logic: 

// Engine Dispatch Logic: src/routes/rm.routes.js (assignRsmForDocComplete)
const loanType = application.loanType;
let targetAsmId = null;

if (loanType === "PERSONAL") {
  // Dispatches to dedicated Personal Credit Manager
  targetAsmId = rm.personalAsmId || rm.personalRsmId;
} 
else if (loanType === "BUSINESS") {
  // Dispatches to dedicated MSME/Business Credit Manager
  targetAsmId = rm.businessAsmId || rm.businessHomeAsmId || rm.businessRsmId;
} 
else if (["HOME_LOAN_SALARIED", "HOME_LOAN_SELF_EMPLOYED", "LAP_SALARIED", "LAP_SELF_EMPLOYED", "LAP"].includes(loanType)) {
  // Dispatches to dedicated Mortgage / LAP Credit Manager
  targetAsmId = rm.homeLapAsmId || rm.businessHomeAsmId || rm.homeLapRsmId;
}

if (!targetAsmId) {
  throw new Error(`RM [${rm.firstName} ${rm.lastName}] has unassigned ASM slot for loan vertical [${loanType}]. Contact Administrator.`);
}

// Atomically bind application to specialized vertical
application.asmId = targetAsmId;
application.rsmId = asm.rsmId || asm.asmId;
application.status = "DOC_COMPLETE";
Guaranteed Cross-Vertical Immunity

Because the dispatch logic checks application.loanType at the moment of document certification, a Home Loan or LAP mortgage application will never reach a Personal Loan ASM. Every file lands on the desk of an underwriter specialized in that exact asset class.

Bank RM Network & PAN India Engine

Managing physical branch networks alongside nationwide digital lending desks with automated search fallback.

1. Local Branch Desks vs. PAN India Digital Desks

Financial aggregation requires managing two completely different operational relationships:

Local Branch RMs (Physical) City Scope

Use Case: Physical file logins requiring local branch inspection, property verification, and regional valuations.

Config: isPanIndia: false, State: Maharashtra, City: Pune (Wakad).

PAN India Central Desks (Digital) Nationwide Scope

Use Case: Digital lending platforms, fintech NBFCs, and central loan factories accepting applications from any pin code in India.

Config: isPanIndia: true, State: PAN India, City: All Cities.

2. Automated Search Inclusion Algorithm

When an ASM in Pune searches for Personal Loan lenders for a Pune customer:

  • The query matches local Pune branch RMs.
  • The query automatically surfaces all PAN India RMs, because nationwide lenders accept files from Pune as well!
  • The results table marks nationwide lenders with the 🌍 PAN India badge and displays "All Cities (Nationwide)" in the location column.
// Query Filter Logic: src/routes/rsm.routes.js & src/routes/admin.routes.js
if (query.state) {
  const stateTrimmed = String(query.state).trim();
  if (stateTrimmed.toLowerCase() === "pan india") {
    filter.$or = [
      { state: { $regex: /^pan\s*india$/i } },
      { isPanIndia: true }
    ];
  } else {
    // Return local state lenders PLUS nationwide central desks
    filter.$or = [
      { state: stateTrimmed },
      { isPanIndia: true },
      { state: { $regex: /^pan\s*india$/i } }
    ];
  }
}

Chapter 10

User Manual: Operations & Credit Underwriting

Standard operating procedures for central credit operations, document audit, and compliance scrutiny.

1. Document Audit Checklist

  • PAN Card: Verify name against Aadhaar and NSDL database. Confirm date of birth and clear photograph.
  • Aadhaar Card: Ensure both front and back are visible with complete 12-digit UID and address.
  • Salary Slips: Check employer name, PF deductions, professional tax, and net pay. Ensure all 3 slips are consecutive.
  • Bank Statements: Verify salary credit narration matches employer name. Inspect for inward cheque bounces or EMI return charges.
  • Business Financials: Verify CA seal, UDIN number, depreciation schedules, and matching turnover between GSTR-3B and P&L statements.

2. Document Rejection Protocol

Never reject an entire application if only one document is defective. Open the defective document viewer, click Reject, and choose or type a clear rejection reason:

  • "Bank statement is password protected. Please upload an unlocked PDF."
  • "Salary slip for August is cut off at the bottom. Upload full page."
  • "ITR Ack is missing Computation of Income page."

1. Customer Engine Architecture & Zero-Error Safeguards

The Customer application service (/api/customer/create-applications) is engineered to process all 4 loan categories without runtime errors, payload drops, or orphaned files. It enforces four automated safeguards:

Dynamic Conditional Schema Mapping Field Isolation

Depending on the selected loanType, the backend dynamically isolates and binds specialized metadata without throwing schema validation errors:

  • Salaried Loans (PL / HL / LAP): Binds employmentInfo (Company, Designation, Monthly Salary, Experience).
  • Self-Employed Loans (BL / HL / LAP): Binds businessInfo (Shop/Firm Name, GST, Annual Turnover).
  • Mortgage Loans (HL / LAP): Binds propertyInfo (Property Type, Market Value, Physical Address).
Employee ID Race Condition Guard Duplicate Protection

High-volume customer registrations can trigger MongoDB unique key collisions (E11000 duplicate key: employeeId). The system employs an automatic 5-attempt exponential backoff retry loop that regenerates unique IDs in memory, ensuring 100% registration success even under heavy concurrent traffic.

Zero-Orphan Partner Routing Hierarchy Binding

When a borrower applies via a Partner's referral link, they are automatically tied to that Partner and the Partner's RM. If a borrower arrives directly via organic search, the resolveDefaultCompanyPartner() resolver binds them to the corporate desk, guaranteeing an RM is always assigned to verify documents.

60-Day Reapplication Guard Underwriting Policy

Prevents duplicate submissions if a customer already has an active application under credit assessment, protecting the borrower's CIBIL score from repeated hard enquiries across different banks.

3. Borrower Step-by-Step Operations Manual for All 4 Loan Types

A. Personal Loan (Salaried Applicants)

  1. Open the Customer Application portal or partner referral link. Select Personal Loan.
  2. Enter your personal particulars: Full Name (as per PAN), Mobile Number, Email, PAN Number, Date of Birth, and Current Residential Address.
  3. Enter Employment Information: Company Name, Official Designation, Net Monthly In-hand Salary, and Total Work Experience in years.
  4. Upload Mandatory Documents:
    • PAN Card photo/PDF
    • Aadhaar Card (front & back)
    • Latest 3 Months Salary Slips (consecutive)
    • Latest 6 Months Salary Bank Account Statement (PDF downloaded from NetBanking)
  5. Review summary and click Submit Loan Application. An instant tracking ID (e.g. DS2026-08119) will be displayed.

B. Business Loan (MSME, Traders, Self-Employed)

  1. Select Business Loan on the loan application screen.
  2. Enter Applicant Particulars and Business Details: Registered Firm Name, Constitution (Proprietorship / Partnership / Pvt Ltd), GST Number, Annual Turnover in Lakhs, and Business Address.
  3. Upload Mandatory Financial Documents:
    • Applicant PAN & Aadhaar
    • Firm Registration Certificate (GST Certificate / Udyam Aadhar / Shop Act)
    • 12 Months Current Bank Account Statement (PDF)
    • Latest 2–3 Years ITR with Computation of Income, Balance Sheet, and P&L statements
  4. Submit application. Your assigned RM will review the turnover metrics and initiate bank file login.

C. Home Loan (Purchase / Construction / Balance Transfer)

  1. Select Home Loan. Indicate applicant employment profile: Salaried or Self-Employed.
  2. Fill in Property Information: Property Type (Flat, Independent Villa, Plot + Construction), Estimated Market Value, and Property Location Address.
  3. Upload Income & Property Documents:
    • Applicant & Co-Applicant KYC (PAN & Aadhaar)
    • Income Proofs (Salary Slips for Salaried; 3 Yrs ITR for Business)
    • Allotment Letter / Draft Agreement to Sale
    • Property Title Deeds and Approved Construction Sanction Plan
  4. Submit application. The file routes immediately to the specialized Home/LAP credit desk.

D. Loan Against Property (LAP / Mortgage Top-Up)

  1. Select Loan Against Property (LAP).
  2. Enter Required Loan Amount, Tenure, and Property Details: Commercial, Residential, or Industrial Property Type, Approximate Market Value, and Existing Outstanding Loan Balance (if Balance Transfer).
  3. Upload Collateral Documents:
    • Applicant & Co-Applicant KYC
    • Full Income Proofs (ITR / Salary Slips / 12 Months Bank Statement)
    • Complete Chain of Title Deeds (minimum past 13–30 years)
    • Approved Layout Plan, Property Tax Receipt, and Electricity Bill
    • Sanction Letter & Foreclosure Statement of existing lender (for BT cases)
  4. Submit application. The file routes directly to the Home/LAP underwriting vertical for legal and technical valuation.

2. Mathematical Calculation Model

// Commission Computation Formula
BaseCommission = DisbursedAmount * SlabPercentage;
TDS_Deduction  = BaseCommission * 0.05; // 5% Section 194H TDS
NetPayable     = BaseCommission - TDS_Deduction;

1. Industry Terminology Glossary

  • DSA (Direct Selling Agent): An authorized third-party sales representative or firm that originates loan applications for banks and NBFCs.
  • LOS (Loan Origination System): The core internal credit assessment software used by banks to process loan files from application to disbursal.
  • LAN (Loan Account Number): The official unique identification number assigned to a borrower's file once logged into a bank's LOS.
  • BT (Balance Transfer): Refinancing an existing high-interest loan from one bank to a new bank with lower interest rates or top-up capital.
  • CIBIL / Experian / CRIF: Credit information bureaus in India providing credit history scores ranging from 300 to 900.
